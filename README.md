🌍 GeoSculpt

Single RGB Aerial Image → Relative Depth → Metric DSM → 3D Scene

GeoSculpt is a web-deployable prototype for reconstructing elevation information
and a lightweight 3D scene from a single RGB aerial/orthomosaic image.

The application wraps the existing GeoSculpt processing pipeline and exposes it
through a browser-based Gradio interface.

What the demo accepts

RGB input

Supported uploads:

.tif

.tiff

.png

.jpg

.jpeg

GeoTIFF is the preferred input for georeferenced/metric processing.

Optional GCP input

GCP files may be supplied as CSV or JSON.

CSV format:

id,x,y,z
GCP1,....
GCP2,....
GCP3,....

For the current Spanish georeferenced workflow, the web UI defaults the GCP
CRS to:

EPSG:25830

when no other value is entered.

Output products

The application attempts to expose the products generated by the underlying
GeoSculpt pipeline:

dsm.tif — metric Digital Surface Model

ndsm.tif — metric normalized DSM / above-ground height

dtm.tif — metric Digital Terrain Model

buildings.geojson — extracted building objects, when available

trees.geojson — extracted tree objects, when available

scene.glb — reconstructed 3D scene, when available

calibration metadata and run metadata

Calibration

For GCP-based metric calibration, the pipeline uses the affine relationship:

z_ref − DTM = aR + b

where:

R = relative depth / relative surface prediction

DTM = terrain elevation

z_ref = GCP reference elevation

a = fitted scale

b = fitted offset

The metric above-ground height is then:

AGL = aR + b

and the metric DSM is:

DSM = DTM + AGL

The existing project code performs the full calibration and DSM composition;
this web application does not replace that logic.

Deployment

This Space is intended for Hugging Face Spaces with the Gradio SDK and
ZeroGPU.

1. Create the Space

Create a new Hugging Face Space and select:

SDK: Gradio

2. Enable ZeroGPU

In the Space settings, select the ZeroGPU hardware/runtime option.

ZeroGPU is shared infrastructure. GPU availability and usage quota are
managed by Hugging Face, so live inference can depend on current queue/quota
conditions.

3. Upload the project

Push the following into the Space repository:

app.py
run.py
requirements.txt
models/best.pth
external/Depth-Anything-V2/
data/geoids/es_ign_EGM08_REDNAP.tif

Also push every Python module imported by run.py, including the current
GeoSculpt source files.

4. Start the Space

Hugging Face builds the environment from requirements.txt and starts
app.py.

The public application will then be available from the Space URL.

Free-demo strategy

This deployment is designed to avoid paid dedicated GPU hardware.

For a competition/judge demonstration:

Keep the uploaded test scene reasonably small.

Prefer a georeferenced GeoTIFF when metric products are required.

Keep the model checkpoint already present in the Space repository.

Avoid unnecessary repeated inference calls because ZeroGPU is shared and
quota-limited.

Keep a known-good demo scene/output available separately when possible.

Important project status

The web wrapper is intentionally thin: the existing GeoSculpt pipeline remains
the source of truth for metadata, tiling, inference, DEM alignment, ground
estimation, calibration, and metric composition.

The final 3D reconstruction and Three.js viewer are connected only when their
corresponding project files are present in the repository.

For the metric orchard workflow, calibration should be validated with
non-ground height information before treating extracted metre-based tree or
building heights as final.

Troubleshooting

Checkpoint not found

Make sure this file exists:

models/best.pth

Depth Anything V2 directory not found

Make sure the complete source directory exists:

external/Depth-Anything-V2/

run.py is missing

Place the project run.py at the repository root.

FABDEM failure

The pipeline uses the existing FABDEM acquisition/alignment logic. Check that
the Space can reach the required FABDEM sources and that the scene has valid
georeferencing for metric processing.

CPU / CUDA errors

ZeroGPU must be enabled for live GPU inference. The wrapper requests a GPU only
while the pipeline function is running.
